# 评测

## 数据

`eval/fixtures/` 里有两份为本仓库原创的字幕样例，模仿真实 B 站视频的说话方式：开场寒暄、口播广告、重复强调、跑题和三连求关注都有。

| 样例 | 时长 | 字幕行数 | 标注 |
|---|---|---|---|
| 大模型 Agent 入门：从 ReAct 到工具调用 | 6 分钟 | 110 | 12 个块（4 段注水，5 段关键干货），10 个问题 |
| 十年老厨师教你做红烧肉 | 4 分钟 | 88 | 11 个块（5 段注水，5 段关键干货），8 个问题 |

样例按“块”标注，脚本把块转换成带时间戳的字幕行，所以标签永远和文本对得上。每个问题标了答案所在的块，并分成两类：“原词提问”（用了 UP 主原话里的词）和“换说法提问”（意思一样，用词不同）。

## 离线检索评测（不需要 Key，CI 每次都跑）

```bash
npm run eval -- --offline
```

在相同的字幕窗口上，对比 v0 的关键词打分和 v1 的 BM25 + MMR：

| 检索方法 | Recall@1 | Recall@3 | Recall@5 | MRR | 原词提问 R@3 | 换说法提问 R@3 |
|---|---|---|---|---|---|---|
| v0 关键词匹配（旧版） | 72% | 78% | 78% | 0.75 | 100% | 60% |
| BM25 + MMR（新版，无 Key） | 89% | 94% | 94% | 0.92 | 100% | 90% |

差别全部出在“换说法提问”上。v0 只认整句原样出现，或者问题里的字二元组出现在字幕里；一个二元组都对不上时，它直接返回空结果。三个 v0 答不出、新版排在第一的问题是：

- “炖多久”：字幕原话是“炖一个小时”，没有“炖多”或“多久”这两个二元组；BM25 靠稀有的单字“炖”就能命中。
- “吃起来太油腻怎么办”：字幕说的是“怕腻”“解腻”；
- “怎么知道改了 prompt 以后效果是变好还是变差”：字幕说的是“评测”“变好了还是变差了”。

BM25 按词计分，并用 IDF 给常见词降权，所以部分重合也能把正确片段排上来。

样本只有 18 个问题，数字只用来说明方向，不代表大规模基准。

## 完整评测（需要模型）

```bash
OPENAI_BASE_URL=... OPENAI_API_KEY=... OPENAI_MODEL=... npm run eval
# 可选：OPENAI_CHEAP_MODEL、OPENAI_EMBEDDING_MODEL；也会读取 .env.local 里的 VITE_* 变量
```

额外输出：

- **检索**：加上片段摘要作为上下文后的 BM25；配置了 Embedding 时，再加一行“BM25 + 向量 + RRF + MMR”混合检索。
- **分析流水线**：注水识别按秒计算的 Precision / Recall / F1；新版重点选择与 v0“TopK=6”分别覆盖了多少关键块、有几个落在注水段；平均落地分；章节数；调用次数、token、耗时。
- **问答 Agent**：引用命中正确时间段的比例、带引用的回答比例、引用落在已检索证据内的比例、平均步数和 token。

结果写入 `eval/results/latest.md` 和 `latest.json`（不提交进仓库）。
