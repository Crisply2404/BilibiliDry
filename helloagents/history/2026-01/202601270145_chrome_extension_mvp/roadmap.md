# 里程碑与一周交付节奏（可投递版本）

> 目标：7 天内产出可演示、可写简历的作品闭环（热力图进度条 + 跳过注水 + Markdown 导出 + 跨视频搜索）。

---

## 交付分批（重要且容易先出）

### P0（必须，先做）
1. **扩展骨架跑通**：MV3 + settings（Key 配置）+ content script 注入（能在 B站视频页显示 UI）
2. **字幕(仅CC)获取**：能稳定拿到时间戳字幕
3. **一键跳过注水（先用规则/简单模型）**：哪怕识别不完美，也能形成“可用闭环”

### P1（紧随其后）
4. **增量分析（边看边出）**：chunks + 缓存 + 断点续跑；热力图逐步变准确
5. **Markdown 导出**：复制/下载

### P2（价值高但更费工程）
6. **跨视频搜索（先关键词，后语义）**
   - v1：关键词检索（不依赖 embedding，最快交付）
   - v2：语义检索（embedding + cosine，成本与限流要控）

---

## Day-by-day（建议按此执行）

### Day 1（今天）
- 产出：可加载的 MV3 扩展 + 设置页（Key/开关/清空数据）+ 在 B站视频页显示一个浮层入口
- 验收：`chrome://extensions` 加载 unpacked → 打开任意 `bilibili.com/video/*` → UI 可见

### Day 2
- 产出：字幕获取（仅 CC）+ 解析为时间戳片段 + 本地存储（videos/segments）
- 验收：打开视频后，能显示“字幕可用/不可用”；有字幕时能看到解析出的前 N 条字幕时间戳

### Day 3
- 产出：注水跳过 v1（规则/heuristics）：根据常见注水词（开场、三连、感谢观看、抽奖、广告等）给出初版 WATER 段；能一键跳过
- 验收：按钮可把播放位置跳到“非注水”区域；哪怕误判，也要保证不死循环/不超界

### Day 4
- 产出：Gemini 分段识别 v1（Flash）+ chunk 调度 + 热力图叠加到播放器进度条（增量更新）
- 验收：视频打开后 ≤30s，热力图出现第一批结果；随后每个 chunk 完成会更新

### Day 5
- 产出：Markdown 导出（复制/下载），内容结构固定（摘要→要点→时间索引→原视频链接）
- 验收：导出内容可直接粘贴到 Notion，时间戳链接可跳回 B站对应时间

### Day 6
- 产出：跨视频搜索 v1（关键词检索：标题/摘要/字幕片段）+ 结果跳转
- 验收：至少分析过 2-3 个视频后，搜索能返回结果并跳转到时间点

### Day 7（投递准备）
- 产出：作品 README（架构图、指标、隐私说明、演示 GIF/视频）、简历要点、面试讲解稿（5 分钟版）
- 验收：可以对照 `helloagents/wiki/resources/JD.md` 把关键词全部“对上”（Memory/检索/调度/安全/性能/评测）
