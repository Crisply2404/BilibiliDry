# 变更提案: Reflection Gate（字幕证据对齐校验）

## 需求背景

当前 BilibiliDry 的核心产物是：
- “注水/干货”时间分段（segments）
- 干货摘要（summary）
- 热力图跳过与本视频搜索

但在面试与真实使用场景里，最大的“信任风险”不是功能缺失，而是**幻觉/不对齐**：
- 摘要看起来很合理，但字幕证据并不支持
- 干货段时间戳不准，点击跳转后发现内容对不上

因此需要一个可演示、可解释、可量化的机制：在生成结果后做二次校验，并把校验结论展示给用户（同时用于自动降置信度）。

## 产品分析

### 目标用户与场景
- **用户群体:** B 站网课/访谈/播客的高频学习者（长视频、信息密度不均、反复跳转定位）
- **使用场景:** 边看边用热力图跳过注水、快速定位干货、把关键点导出为 Markdown
- **核心痛点:** 产物如果与字幕不对齐，会直接摧毁信任，用户会认为“AI 不靠谱”

### 价值主张与成功指标
- **价值主张:** “不是更会总结，而是能证明自己没瞎编（有证据、有解释、能纠错）”
- **成功指标（v1）:**
  1) 分析完成后，对 TopK 干货段给出 `pass/weak/fail` 结论与一句话原因
  2) `weak/fail` 自动降置信度并在 UI 明确标注“需人工确认”
  3) 支持展开查看字幕证据片段（用户可一眼判断对齐与否）
  4) 额外耗时可控（默认只抽样 3~6 段，目标 < 10 秒）

### 人文关怀
- **隐私:** 全流程 BYOK；只在本地处理字幕与结果；不引入自建后端收集用户数据
- **可解释:** 失败不“硬删”，只降置信度并展示原因与证据，尊重用户判断

## 变更内容
1. **Reflection Gate**：分析结束后抽样校验关键干货段，与字幕证据做对齐审计并产出 verdict/score/reason/evidence。
2. **可视化与可解释**：Overlay 与 Dashboard 展示校验结果；支持展开查看字幕证据片段。
3. **自动置信度修正**：当 verdict=weak/fail 时自动降 confidence，避免误导热力图与搜索重排。

## 影响范围
- **模块:**
  - background：`src/background/analyze.ts`（新增校验阶段）
  - llm：`src/background/llm.ts` + `src/background/openai.ts`（新增校验接口）
  - storage/types：`src/shared/messages.ts`、`src/background/db.ts`、`types.ts`（新增校验字段/消息）
  - ui：`src/content-script/overlayApp.tsx`、`components/*`、`src/dashboard/*`（展示校验结果）
  - export：`src/background/markdown.ts`（导出包含校验标记）

## 核心场景

### 需求: 关键干货段校验与可解释展示
**模块:** background + ui

#### 场景: 分析完成后自动校验
- 条件：字幕可用（CC），完成分块分析并产出 segments
- 预期结果：
  - 立即展示分析结果（不等待校验）
  - 同时开始校验（校验中状态可见）
  - 校验完成后 UI 自动刷新，显示每段 `pass/weak/fail` 与 reason

#### 场景: 用户展开查看证据
- 条件：某段标记为 weak/fail
- 预期结果：
  - 展示该段时间窗附近的字幕证据（前后扩 10 秒）
  - 用户能快速判断：是时间戳偏移、还是总结过度推断

## 风险评估
- **风险:** 额外延迟与成本上涨
  - **缓解:** 只抽样校验 TopK，限制证据长度与候选段数量
- **风险:** OpenAI-compatible 兼容性差异（尤其是三方网关）
  - **缓解:** 先使用现有 `chat/completions` 路径；如不兼容再单独补 `/responses` fallback（本次不做）
- **风险:** 校验结果与落库时序不一致导致 UI 闪烁
  - **缓解:** overlay 以“内存态结果”优先渲染；校验结果以增量更新方式覆盖
