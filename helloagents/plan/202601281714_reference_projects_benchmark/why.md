# 方案包：参考项目拆解与 BilibiliDry 对标升级（业界水平）

## 1) 背景与动机

BilibiliDry 当前已完成 Chrome MV3 扩展 MVP：基于字幕（CC）做分块增量分析，在播放器上渲染“干货热力图”，支持一键跳过注水、Markdown 导出、跨视频搜索（本地 embedding + cosine）。

为了把项目做成“业界水平”（可长期维护、可扩展、可投递/可开源运营），需要对标同类成熟项目，明确：
- 业界常见的端到端链路与工程化做法
- BilibiliDry 的差异化价值与短板
- 可执行的升级路线（阶段、里程碑、风险与验收标准）

## 2) 对标对象与我们要学什么

本次对标 `reference/` 下（排除 `bilibilidry0`）项目：
- AI-Video-Transcriber：自托管“下载/ASR/摘要”流水线、任务化进度与 Docker 部署
- BibiGPT-v1：Edge 端流式摘要 + 缓存 + 限流 + 可观测（可公网上线运营）
- bilibili-video-summary-agent：高可靠字幕/转录/时间戳要点与 CLI 工程化（含单测）
- SummaryExpressive：移动端 BYOK 产品化（多 Provider、分享即摘要、历史搜索、隐私）
- VideoAgent：复杂任务的图编排与反思闭环（长期演进的架构启发）

**我们的目标不是复制它们**，而是提炼“可迁移能力”，并在“纯扩展 + BYOK”为主的约束下落地。

## 3) 成功标准（验收）

### 3.1 报告产出（本轮必须）
- 每个参考项目一份“非常详细”的拆解报告（含架构/流程/关键策略/风险/可借鉴点）
- 一份 BilibiliDry 对标报告：能力矩阵、差距、目标架构、分阶段路线图

### 3.2 升级方案（本轮必须）
- 形成可执行的任务清单：阶段划分、优先级、验收标准、风险与回滚点
- 明确“默认路径（纯字幕）”与“可选增强（本机伴生服务/ASR 兜底）”的产品策略边界

## 4) 风险与约束

- **Chrome MV3 限制**：service worker 可能休眠导致长任务中断，需要可恢复/断点续跑与（必要时）offscreen 文档。
- **成本不可控**：BYOK 仍可能被误触发导致用户扣费，需要缓存/去重/预算与降级策略。
- **合规/隐私**：字幕内容会发送给所选 LLM 提供商，必须在 UI 与文档中清晰告知，并提供清理与禁用记忆选项。
- **范围控制**：BilibiliDry 当前定位“仅字幕”，ASR 兜底应作为可选增强，不强行扩大 MVP 范围。
