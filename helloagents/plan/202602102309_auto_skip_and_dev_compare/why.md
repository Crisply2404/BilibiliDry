# 变更提案: 自动跳过注水（更符合直觉）+ 开发者对比视图

## 需求背景
目前「自动跳过注水」的体验有点反直觉：
- 我只是点了“自动跳过”，它有时会立刻把进度往后跳一段（哪怕我当时不在注水段），而且界面上也不够明显地告诉我现在到底开没开。
- 我把进度条拉到“快进入注水段”之前，想等它自动绕开，但它有时没绕开。
- 我希望的规则更简单：**用户自己拖进注水段 = 我尊重用户选择，让他看；正常播放即将进入注水段 = 帮他绕开。**

另外，面试/自证效果上，我们已经有 Model Cascade 指标、关键干货校验等信息，但这些不该给普通用户看；我希望在「开发者模式」下有一个更直观的“对比视图”，方便我解释“为什么我们这样设计、有什么收益”。

## 产品分析

### 目标用户与场景
- **普通用户**：看 B 站长视频（网课/访谈），想省时间，不想被打断。
- **开发者（你）**：需要验证功能是否真的有效、是否稳定，以及面试时能讲清楚“设计取舍”和“收益数据”。

### 价值主张与成功指标
- **价值主张**：减少无效时间，让“该跳就跳、想看也能看”。
- **成功指标（可验收）**：
  1. 开关有明显状态：用户能一眼看出自动跳过是开/关。
  2. 正常播放时：进入注水段会自动跳到注水段后面（按你勾选的注水类别过滤）。
  3. 用户手动拖进注水段：不强制跳过（直到这段注水自然结束）。
  4. 注水原因展示为中文标签（例如：重复/广告/无信息增量），避免出现英文枚举值。
  5. Dashboard 不再是“黑屏假播放器”，至少能做到：点击片段/卡片能跳到视频对应时间点；最好能直接在 Dashboard 内播放（有技术风险会给 fallback）。
  6. 面试/验证：在开发者模式下能看到“本次 vs 上次”或“不同 run 的对比”，能讲出收益点。

### 人文关怀
- 不强迫：用户想看注水段也能看（手动拖进去就是“我想看”的信号）。
- 透明：告诉用户当前开关状态，减少“我刚刚发生了啥”的疑惑。

## 变更内容
1. 优化自动跳过的行为规则（按“尊重用户主动操作”来设计）。
2. UI 只保留「开关自动跳过」：不提供“点一次跳一次”的手动跳过按钮（避免产品形态混乱）。
3. 自动跳过开关的状态提示更明显（避免“到底开没开”的困惑）。
4. 注水原因在卡片/热力图上用中文标签展示（重复/广告/无信息增量等）。
5. Dashboard 完善：开发者对比视图 +（尽可能）真实播放/跳转体验 + 逻辑积木初版。
6. 冒烟验证清单：把关键场景跑一遍，避免“看起来行但边角不行”。

## 核心场景

### 需求: 自动跳过（更符合直觉）
**模块:** content-script

#### 场景: 正常播放即将进入注水段
当用户正常播放快进入注水段时：
- 自动跳过开启 → 自动跳到该注水段后面
- 自动跳过关闭 → 正常播放

#### 场景: 用户手动拖进注水段
当用户明确把进度条拖进注水段：
- 不强制跳过（用户就是想看，这时候要尊重用户）

#### 场景: UI 状态可见
用户在浮层里能明确看到：
- 自动跳过：已开启 / 已关闭

#### 场景: 注水原因展示为中文标签
用户在浮层的“卡片/热力图提示”里看到的注水原因：
- 显示为中文标签（重复/广告/无信息增量/寒暄/跑题）
- 不出现类似 `REPEAT/AD/NO_NEW_INFO` 这种英文枚举值

### 需求: 开发者对比视图
**模块:** dashboard

#### 场景: 开发者模式下看对比
开启开发者模式后：
- 能看到“不同分析 run”的对比信息（成本/耗时/校验结果等）
- 普通用户模式下完全不显示这些面板

### 需求: Dashboard 可用性完善
**模块:** dashboard

#### 场景: Dashboard 里能“看/跳”
- 最低目标：点击卡片/片段 → 打开 B 站并跳到对应时间点
- 进阶目标：Dashboard 内嵌播放器可播放（如果被 B 站限制，则自动降级到“打开新标签页跳转”）

#### 场景: 逻辑积木能看到东西
- 最低目标：先有“可用的初版”（哪怕是简单分组/占位），不要永远空白
- 进阶目标：用 LLM 产出 Background/Problem/Solution/Case 四类积木，并能点击跳到对应片段

## 风险评估
- **风险**：误判导致“该看不让看/不该跳却跳”。  
  **缓解**：把“用户手动拖进注水段”作为明确的“我想看”信号；并在 UI 上给出开关状态提示。
- **风险**：B 站页面里可能有多个 `<video>`，取错元素会导致跳转不生效。  
  **缓解**：优先选择“可见且面积最大”的 video 元素。
- **风险**：Dashboard 内嵌播放器可能会被 B 站的限制（例如不允许 iframe）。  
  **缓解**：做降级方案：点片段/卡片 → 新标签页打开并定位时间点（确保“至少能用”）。
