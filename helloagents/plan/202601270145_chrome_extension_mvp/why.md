# 变更提案: Chrome 插件 MVP（纯扩展本地化）

## 需求背景
长视频（网课/访谈）“注水内容多、干货定位难”，用户常见行为是手动拖动进度条找关键点，成本高且容易错过。我们要把“干货密度”变成播放器的一等公民：在进度条上直接呈现，并支持一键跳过注水、导出笔记、跨视频搜索。

## 产品分析

### 目标用户与场景
- **用户群体:** B站网课/访谈/长视频的学习者与知识型内容消费者
- **使用场景:** 边看边学、回看复习、跨视频查某个概念
- **核心痛点:** 拖进度条找不到干货；看完难沉淀；跨视频知识回忆困难

### 价值主张与成功指标
- **价值主张:** 像“云录制智能章节”一样，为每个长视频生成“自动避水”的智能进度条与要点索引
- **成功指标（MVP）:**
  - 首次打开视频后 ≤30s 出现第一批热力图结果（覆盖前 3-5 分钟或前 N 个 chunk）
  - 一键跳过注水成功率 ≥90%（用户主观：减少无效观看）
  - 导出 Markdown 可直接粘贴到 Notion/Obsidian
  - 跨视频搜索：Top-5 至少命中 1 条可用结果（带时间戳可跳转）

### 人文关怀
- **隐私:** 用户 API Key 仅本地存储；字幕与向量默认仅在本地（IndexedDB）
- **透明:** UI 明确提示“仅 CC，非 OCR”；允许用户一键清空本地记忆

## 变更内容
1. 将现有 Vite+React Demo 演进为 Chrome MV3 插件
2. 接入 B站 CC 拉取与增量分析（边看边出）
3. 实现一键跳过注水 + 自动跳过开关
4. 实现 Markdown 导出（复制/下载）
5. 实现跨视频语义检索（本地 embedding）

## 影响范围
- **模块:** extension / agent / memory / notion_export / ui
- **文件:** 将新增 MV3 目录结构与存储层；现有 Demo 代码会被迁移/复用
- **API:** 无对外 HTTP API（内部 message API）
- **数据:** 新增 IndexedDB schema（segments/embeddings/videos）

## 核心场景

### 需求: 一键跳过注水片段
**模块:** extension + ui
在 B站视频页提供按钮，点击即可跳过当前/下一个注水片段。

#### 场景: 用户边看边跳过
打开视频并开始播放
- 预期结果：点击“跳过注水”→ 播放器 seek 到下一个干货片段开头

### 需求: Notion 导出（Markdown）
**模块:** notion_export
将本视频分析结果导出为 Markdown，用户可复制/下载。

#### 场景: 复制到 Notion
用户点击“导出”
- 预期结果：生成结构化 Markdown（摘要、要点、时间索引、链接）

### 需求: 跨视频搜索
**模块:** memory + ui
用户输入自然语言 query，在本地索引中检索相关片段。

#### 场景: 学过的内容回忆
用户搜索“RSC 序列化”
- 预期结果：返回多个视频的相关片段（含时间戳），点击可跳转播放

### 需求: 边看边出（低等待）
**模块:** agent
增量分块分析字幕，先出可用热力图与跳过列表。

#### 场景: 首屏快速可用
用户打开视频后等待不超过 30 秒
- 预期结果：热力图出现第一批结果，跳过按钮可用

## 风险评估
- **风险:** B站 DOM/字幕接口变化导致抓取失败
  - **缓解:** 多策略获取（DOM + API），失败回退为“仅导出字幕”
- **风险:** MV3 service worker 易挂起，增量任务中断
  - **缓解:** 任务分块 + 可恢复（断点续跑），必要时引入 offscreen 文档
- **风险:** 成本/延迟不可控（用户 Key 触发限流）
  - **缓解:** 缓存、并发限制、可暂停、优先产出跳过列表
